# MOBY Import Reviewer

The `/import-review` page is a static, client-side review surface for MOBY import sidecars. It proves that a sidecar generated outside this repo can be consumed by `trackingthc.com` and turned into a readable import review workflow.

## Sample File

The current page loads one bundled sample:

```text
public/samples/moby-import-example.json
```

In the browser, the file is fetched from:

```text
/samples/moby-import-example.json
```

The sample represents a versioned `moby-import.json` sidecar generated by `trackingthc-import-mapper`.

## Expected Sidecar Shape

The viewer expects a JSON object with these top-level fields:

```text
schemaVersion
generatedBy
generatedAt
mappingProfile
importRun
validationIssues
packages
```

Expected sections:

- `schemaVersion`: version of the MOBY import sidecar contract.
- `generatedBy`: tool or package that generated the sidecar.
- `generatedAt`: timestamp for sidecar generation.
- `mappingProfile`: source system and source-to-canonical field mappings.
- `importRun`: run metadata, status, source file, and summary counts.
- `validationIssues`: warnings or errors found during mapping/normalization.
- `packages`: normalized package records ready for review.

## Display Sections

The page renders the sidecar as:

- Schema metadata: schema version, generator, and generation timestamp.
- Import summary: run ID, source, status, rows processed, warning count, package count, and source file.
- Mapping profile: source field, canonical field, and mapping status.
- Validation issues: severity, code, field, row number, and message.
- Packages: package label, product name, quantity, unit cost, total cost, and vendor.

## Fallback Behavior

- Missing fields render as —.
- Missing or empty mapping, validation issue, or package arrays render empty-state messages.
- Invalid cost rows remain unresolved instead of being guessed or repaired in the UI.
- The known bad cost sample row stays visibly unresolved so reviewers can trace it back to the validation issue.

## Why This Matters

The reviewer proves the repo-to-repo handoff:

```text
moby-core -> trackingthc-import-mapper -> trackingthc.com
```

`moby-core` defines the shared contract, `trackingthc-import-mapper` generates a versioned MOBY sidecar, and `trackingthc.com` consumes that sidecar without needing mapper internals.

That turns the MOBY sidecar from a contract artifact into a visible review workflow foundation for audit, reconciliation, and finance review.
